# LLM参数微调原理详解

## 1. 微调的基本概念

**什么是微调？** 微调（Fine-tuning）是指在预训练模型的基础上，用特定任务或领域的数据对模型进行进一步训练，从而使模型参数适应新任务的数据分布

[blog.csdn.net](https://blog.csdn.net/weixin_45277161/article/details/131544912#:~:text=* 之后，你又接收到一个类似的图像分类的任务。这时候，你可以直接使用之前保存下来的模型的参数来作为这一任务的初始化参数，然后在训练的过程中，依据结果不断进行 一些修改。这时候，你使用的就是一个 `pre,tuning`。)

。简单来说，我们先有一个在海量数据上训练好的“大语言模型”（LLM），它掌握了一般语言规律；然后我们将它拿到自己的小数据集上接着训练，稍微调整它的参数，使其更适用于特定任务或领域[blog.csdn.net](https://blog.csdn.net/weixin_45277161/article/details/131544912#:~:text=* 之后，你又接收到一个类似的图像分类的任务。这时候，你可以直接使用之前保存下来的模型的参数来作为这一任务的初始化参数，然后在训练的过程中，依据结果不断进行 一些修改。这时候，你使用的就是一个 `pre,tuning`。)。例如，预训练可以看作让模型学会“通用语言”，而微调则是教模型在某个“小领域”里说话。



**为什么需要微调？** 由于预训练模型是在非常通用的大规模数据上学到的，它不一定能直接做好特定的任务。通过微调，模型会在目标任务对应的数据分布上进行校准，更精准地针对该任务进行优化

[zhuanlan.zhihu.com](https://zhuanlan.zhihu.com/p/21445492073#:~:text=大模型为什么需要微调 )

。此外，从零开始训练一个大型模型往往需要海量数据和算力，但很多场景下我们只有有限的标注数据。如果直接用少量数据训练一个大模型，容易**过拟合**或效果不佳；而使用预训练模型微调可以充分利用预训练得到的知识，以较少的数据和计算实现较好的性能[blog.csdn.net](https://blog.csdn.net/weixin_45277161/article/details/131544912#:~:text=在 CNN 领域中，实际上，很少人自己从头训练一个 CNN 网络。主要原因是自己很小的概率会拥有足够大的数据集，基本是几百或者几千张，不像,ImageNet 有 120 万张图片这样的规模。拥有的数据集不够大，而又想使用很好的模型的话，很容易会造成过拟合。)。正如实践中常见的做法：先在大数据集上训练一个模型（预训练），然后将该模型作为起点，在类似任务的小数据集上继续训练（微调），既节省了时间和算力，又取得了不错的效果[blog.csdn.net](https://blog.csdn.net/weixin_45277161/article/details/131544912#:~:text=在 CNN 领域中，实际上，很少人自己从头训练一个 CNN 网络。主要原因是自己很小的概率会拥有足够大的数据集，基本是几百或者几千张，不像,ImageNet 有 120 万张图片这样的规模。拥有的数据集不够大，而又想使用很好的模型的话，很容易会造成过拟合。)。微调与预训练的关键区别在于：预训练面向通用任务，学习通用特征；微调面向具体任务，调整模型使其专注于完成目标任务。



## 2. LLM中的参数结构

**神经网络的基本组成：** 大型语言模型本质上是一个深层神经网络，由多个**层（layer）\**堆叠而成。每一层包含许多\**神经元（neurons）**，神经元之间的连接有对应的**权重参数（weights）**。模型接收输入，通过各层的加权求和和非线性**激活函数**逐层转换，最后输出结果。训练过程中，这些权重会不断调整以降低误差。举例来说，在一个简单的全连接神经网络中，输入经过第一层的线性变换（矩阵乘以权重并加上偏置），通过如ReLU等激活函数引入非线性，再传到下一层，如此叠加多层。模型的**参数**指的就是这些线性变换的权重和偏置项，它们决定了每层的计算。本质上，微调就是要针对新任务**更新这些参数**的值。

**Transformer架构中的关键参数：** 目前大多数LLM使用Transformer架构。Transformer由多层**自注意力（Self-Attention）**和**前馈神经网络（Feed-Forward Network, FFN）**组成。以一个Transformer层为例：首先，模型将输入的词嵌入（embedding向量）投入自注意力机制。自注意力通过学习三个矩阵（可训练参数）将输入变换出**查询（Query）、键（Key）和值（Value）**向量

[cloud.tencent.com](https://cloud.tencent.com/developer/article/2470442#:~:text=)

。具体而言，对于每个输入向量，乘以各自的权重矩阵$W^Q$、$W^K$、$W^V$即可得到对应的$Q$、$K$、$V$表示[cloud.tencent.com](https://cloud.tencent.com/developer/article/2470442#:~:text=)。这些权重矩阵就是Transformer层中的参数之一。接着，使用$Q$、$K$算出注意力权重，对$V$加权求和得到自注意力的输出表示。**多头注意力（Multi-Head Attention）**则是将这种计算复制多份（每份称为一个“头”），每个头有自己的一套$W^Q$/$W^K$/$W^V$参数，关注输入的不同方面，最后将各头的结果拼接起来。这意味着每层Transformer都有多组$Q/K/V$权重参数。



紧随注意力机制之后，是逐位置独立的前馈网络（FFN）。FFN一般包含两层全连接网络：第一层将每个位置的特征映射到更高的隐藏维度，经过激活函数（如ReLU）引入非线性，然后第二层再将其映射回原始维度

[cloud.tencent.com](https://cloud.tencent.com/developer/article/2470442#:~:text=在Transformer模型中，MLP模块通常包含两个线性变换层和一个激活函数。假设输入是自注意力机制的输出，MLP的第一个线性变换层会将输入映射到一个中间维度 （通常比输入维度大）。然后，使用ReLU或其他激活函数引入非线性。最后，第二个线性变换层将中间表示映射回原始输入维度或所需的输出维度。通过这种方式，MLP能够对 自注意力机制的输出进行进一步处理，增加模型的非线性表达能力。)

。例如，如果输入向量维度是$d$，FFN先用一个$d\times h$的权重矩阵把向量升维到$h$（激活后），再用一个$h\times d$的权重矩阵投射回$d$维[cloud.tencent.com](https://cloud.tencent.com/developer/article/2470442#:~:text=在Transformer模型中，MLP模块通常包含两个线性变换层和一个激活函数。假设输入是自注意力机制的输出，MLP的第一个线性变换层会将输入映射到一个中间维度 （通常比输入维度大）。然后，使用ReLU或其他激活函数引入非线性。最后，第二个线性变换层将中间表示映射回原始输入维度或所需的输出维度。通过这种方式，MLP能够对 自注意力机制的输出进行进一步处理，增加模型的非线性表达能力。)。这两个矩阵和其中的偏置也都是参数。此外，每个Transformer子层还有**层归一化（Layer Norm）**的参数（缩放和偏移系数）。Transformer模型的参数因此包括：词嵌入矩阵、每一层中多头注意力的所有权重（每个头的$W^Q$/$W^K$/$W^V$和注意力输出变换矩阵）、FFN的权重和偏置、以及层归一化参数等。一个具有数十层Transformer的LLM往往拥有数十亿计的参数，这些参数共同决定模型的行为，也是微调时要调整的对象。



## 3. 参数微调的方法

大型语言模型的微调有多种策略，主要差异在于**调节参数的多少**以及**如何调整**：

- **全参数微调（Full Fine-Tuning）**：顾名思义，就是对模型的**全部参数**进行微调。我们在下游任务上继续训练模型，使模型的所有权重都根据新数据调整。这通常能够取得最好的任务适应性，因为模型可以自由调整每一层的表示以拟合新任务。然而缺点也很明显：对于数十亿参数的LLM，这种方法计算和存储开销极大

  [ibm.com](https://www.ibm.com/cn-zh/think/topics/parameter-efficient-fine-tuning#:~:text=PEFT 与微调)

  。随着模型规模增长，完全微调要求的计算资源和显存非常高，并且每微调出一个新模型就需要存储一份完整模型的副本，大小和原始模型一样

  [ibm.com](https://www.ibm.com/cn-zh/think/topics/parameter-efficient-fine-tuning#:~:text=PEFT 与微调)

  。例如，GPT-3有1750亿参数，微调后模型仍然是1750亿参数的规模，占用巨大存储。此外，全参数微调如果训练数据很少，还可能导致模型

  过拟合

  或**“灾难性遗忘”**（忘记预训练时学到的通用知识）。因此，全参数微调通常在数据充足、算力充沛的情况下采用，以追求极致的性能。

  

- **部分参数微调（Layer-wise Fine-Tuning）**：为降低开销，我们可以选择**冻结（freeze）**住模型的大部分参数不动，仅微调其中一部分参数。例如，可以只训练模型最后几层的权重，前面的层保持不变。这样需要更新的参数大幅减少，所需显存和计算也明显降低

- **Prefix Tuning / Prompt Tuning（前缀微调/提示微调）**：这两种方法有别于上面几种，因为它们**不直接修改模型的权重**。相反，它们通过调整模型的输入或中间表示来达到效果，被视为“微调”模型的一种手段。**Prefix Tuning（前缀微调）\**是在模型的输入序列前面添加一段可学习的“虚拟向量”（类似于若干个额外的Token embeddings），并\**只训练这些前缀向量**，而模型原有参数保持不变

  [blog.csdn.net](https://blog.csdn.net/dzysunshine/article/details/131590701#:~:text=在学习P)

  。在Transformer中，这些前缀可以被看作额外的提示，参与每层自注意力计算（通常作为每层注意力的键/值的一部分），从而引导模型产生特定任务所需的输出

  [blog.csdn.net](https://blog.csdn.net/dzysunshine/article/details/131590701#:~:text=在学习P)

  。由于训练时仅更新这小段向量的值，所需调节的参数非常少。

  Prompt Tuning（提示微调）**则是更简单的形式：为每个下游任务学习一个特定的**提示词向量

  序列，把它直接拼接在输入文本前，模型仍然保持原参数不变来预测结果

  [blog.csdn.net](https://blog.csdn.net/dzysunshine/article/details/131590701#:~:text=)

  。Prompt Tuning通常只在输入层添加这几个可学习token，不像Prefix Tuning那样在每一层都加前缀。两者本质都是所谓**软提示（Soft Prompt）

  技术：不改变模型结构，而是优化输入端的嵌入。本质上，这些方法将模型

  “指引”**到特定任务，而不需要改动模型内部的上亿权重。

  

  这类方法的优势是微调代价极低——例如只需训练几百个额外向量——尤其适用于超大模型和多任务场景；劣势是对于模型规模较小或任务复杂的情况，效果可能不如直接调整部分权重。近期的研究也在提升软提示方法的效果，例如**P-Tuning v2**结合了深度提示编码和多任务学习等策略，显著提高了Prompt Tuning的性能，使330M到100亿参数各规模模型的提示微调效果都可媲美甚至超过全参数微调

  [blog.csdn.net](https://blog.csdn.net/dzysunshine/article/details/131590701#:~:text=P)

  。总的来说，Prefix/Prompt Tuning提供了一种无需改动模型主体、以极少参数开销定制模型行为的途径，非常适合在现有LLM上快速适配新任务。

  

## 4. 微调过程解析

微调一个LLM通常需要经历以下步骤：

1. **训练数据的准备：** 首先需要收集并整理用于微调的**训练数据**。数据格式和标注要符合任务需求。例如，如果任务是问答系统，需要准备大量问答对（每条包含一个问题及对应答案）；如果是文本分类，则需要带标签的文本样本。接着，对数据进行**清洗和预处理**，保证其质量和一致性

```

for epoch in range(num_epochs):
    for inputs, labels in train_loader:
        outputs = model(inputs)                  # 前向传播
        loss = loss_fn(outputs, labels)          # 计算当前批次的损失
        loss.backward()                          # 反向传播计算梯度

```

## 5. 微调的影响

### 泛化能力与模型拟合

微调的效果不仅在于让模型在训练集上误差降低，更关键的是提升模型在**新样本上的泛化能力**。影响模型泛化能力的因素包括训练数据规模和多样性、模型复杂度、训练轮数以及正则化策略等。**过拟合**和**欠拟合**是评估泛化的两个典型问题：

- *过拟合*：指模型在训练集上表现很好，但在测试/新数据上效果很差。这通常是因为模型“记住”了训练集的细节和噪声，没有学到对新样本有效的一般模式。在微调场景下，过拟合往往发生于训练数据很少且训练轮次过多的情况，或者学习率过大导致模型参数剧烈调整、丢失了原本的通用知识。应对过拟合的方法包括：使用更丰富的训练数据（或数据增强）、加入正则化（例如增加Dropout比例、权重衰减）、在验证集上监控指标并**提前停止**训练。当微调数据非常有限时，采用部分参数微调（如只调最后几层或使用LoRA等）也有助于防止模型过度调整导致泛化能力下降，因为冻结的大部分参数保留了预训练的知识。
- *欠拟合*：指模型在训练集上性能也不佳，说明模型拟合能力不足或训练不到位。可能原因是模型容量不够（在LLM场景下一般不太可能模型太小，更多是数据或训练不足）、特征未充分学习，或者学习率设置过小、优化不足等。遇到欠拟合，可以尝试**增加训练轮数**、**提高学习率**或者更换更强的优化算法，让模型有机会更充分地学习训练数据中的模式。同时也可以检查训练数据是否存在问题（标注不准确或噪声过多）导致模型难以学习。

微调过程应当在**防止过拟合**和**避免欠拟合**之间取得平衡。这通常需要在验证集上观察模型性能随训练进展的变化，来决定是否调整超参数或停止训练

[github.com](https://github.com/naginoa/LLMs_interview_notes/blob/main/大模型（LLMs）微调面.md#:~:text=模型参数迭代实验是指通过多次迭代更新模型参数，以逐步优化模型性能的过程。在实验中，可以尝试不同的参数更新策略、学习率调整方法、正则化技术等，以找到最佳的参数配置 ，从而达到更好的模型性能。)

。例如，如果发现验证集性能在某一轮后开始下降，就可能是过拟合信号，可以提前停止并回滚到最佳轮次的模型；如果训练集和验证集性能都一直较低，则需要考虑模型是否欠拟合，从而增加训练迭代或调整学习率等。良好的泛化意味着微调后的模型不仅记住了训练样本，而且学到了对**同类任务普遍适用**的规律，在同分布的新数据上也能保持高性能。



### 微调效果的评估

在完成微调后，必须通过评估来判断模型在目标任务上的表现是否提升以及是否达到预期。根据任务类型的不同，有相应的**评价指标**可供使用：

- **BLEU**（BiLingual Evaluation Understudy）指标：主要用于评估机器翻译或文本生成类任务的质量。BLEU通过计算模型生成的文本与参考文本在n-gram上的重合程度来衡量输出的准确性和流畅度

  [blog.csdn.net](https://blog.csdn.net/g11d111/article/details/100103208#:~:text=在自然语言处理中的机器翻译任务中%2C BLEU非常常见%2C 它是用于评估 模型生成的句子(candidate)和 实际句子(reference)的差异的指标,虽然这个指标不够完美%2C 但是它有5个非常引人注目的好处(compelling benefits)

  。其分值范围在0到1之间，1表示生成与参考完全一致，0表示完全不相关

  [blog.csdn.net](https://blog.csdn.net/g11d111/article/details/100103208#:~:text=在自然语言处理中的机器翻译任务中%2C BLEU非常常见%2C 它是用于评估 模型生成的句子(candidate)和 实际句子(reference)的差异的指标,虽然这个指标不够完美%2C 但是它有5个非常引人注目的好处(compelling benefits)

  。例如，在机器翻译任务中，给定参考译文，BLEU会统计模型译文有多少单词和短语与参考译文匹配。尽管BLEU有局限（如无法充分捕捉句子语义），但作为自动评价，它提供了一个衡量模型翻译/生成质量的客观标准，BLEU值越高通常表明模型输出与参考答案越接近。

  

- **ROUGE**（Recall-Oriented Understudy for Gisting Evaluation）指标：常用于**文本摘要**和**问答生成**等任务的评估。ROUGE是一组指标族，侧重评估模型生成文本与参考文本的**覆盖率（召回）**

  [blog.csdn.net](https://blog.csdn.net/weixin_46933702/article/details/139574833#:~:text=ROUGE（Recall,量的指标。通过将生成的摘要与参考摘要进行比较，ROUGE可以衡量自动摘要系统的性能，特别在自然语言处理领域中非常受欢迎。)

  。比如ROUGE-N计算n-gram的重叠数量，ROUGE-L计算最长公共子序列。其原理是将机器生成的摘要/回答与人工参考摘要进行比较，统计有多少内容重合

  [blog.csdn.net](https://blog.csdn.net/weixin_46933702/article/details/139574833#:~:text=ROUGE（Recall,量的指标。通过将生成的摘要与参考摘要进行比较，ROUGE可以衡量自动摘要系统的性能，特别在自然语言处理领域中非常受欢迎。)

  。较高的ROUGE分数表示模型生成涵盖了参考摘要中更多的重要信息。在自动摘要任务中，ROUGE是非常流行的评价方式，尤其关注模型是否抓住了源文本的要点。一般来说，

  ROUGE-1

  和

  ROUGE-2

  反映生成与参考在单词、二元词组层面的重叠，

  ROUGE-L

  关注整体句子结构的匹配。微调后如果模型在摘要任务上ROUGE分数显著提高，说明模型更好地提取并表述了关键信息。

  

- **困惑度（Perplexity）**：困惑度常用于评价语言模型本身的好坏，它衡量模型对测试语料的预测能力

  [blog.csdn.net](https://blog.csdn.net/qq_36485259/article/details/136617494#:~:text=困惑度（Perplexity）)

  。形式上，困惑度可以理解为“模型对下一步单词的不确定性”。给定测试集，模型预测得越准确（即给正确单词赋予越高概率），困惑度就越低

  [blog.csdn.net](https://blog.csdn.net/qq_36485259/article/details/136617494#:~:text=困惑度（Perplexity）)

  。数学定义中，困惑度是测试集平均每个词的

  逆概率的几何平均

  。例如，如果一个模型对测试集句子的概率是$P$，困惑度定义为$P^{-1/N}$（$N$为词数）。

  较低的困惑度意味着模型预测序列的平均分支选择更少，也就是模型对语言的掌握更好

  。在微调中，如果我们从预训练语言模型出发针对某领域语料进行微调，通常会观察验证集上的困惑度逐轮下降，表示模型对该领域语言越来越适应。需要注意，不同模型和数据集的困惑度不直接可比，但作为相对指标可用于判断微调过程中模型是否改进。

  

除了上述指标，针对不同任务还有各自惯用的评价标准。例如，分类任务会计算**准确率**、**精确率**、**召回率**、**F1分数**等；问答任务可能关注**准确率**或**BLEU/ROUGE**结合人工评估答案正确性

。在微调实验中，我们通常在验证集上监控这些指标以选择最佳模型，并在独立的测试集上报告最终指标来评估模型泛化性能。若微调后的模型在这些指标上显著优于微调前（甚至优于以前的模型基线），就证明了微调的有效性。



## 6. 实际应用案例

微调技术使得通用的大模型能够适应各式各样的具体应用场景。以下是几个典型案例：

- **问答系统微调：** 大语言模型经过预训练掌握了广博的语言知识，但未必能直接准确回答专业问题。通过在问答语料上微调，可以让模型学会更加精准地回答问题。例如，我们可以使用大规模问答对（如SQuAD数据集）来微调一个预训练模型，让它在给定问题时能够从文本中抽取答案或直接生成答案。微调后模型会针对问答任务进行优化，在答案准确性和相关性上有明显提升。现实中，很多基于LLM的问答系统（如客服问答、知识库问答）都会对模型进行监督微调，使其语气和回答更符合产品需求。经过微调的模型在特定领域的问题上表现得像该领域的“专家”，这正是微调赋予模型的专业能力。

- **代码生成微调：** 微调也广泛应用于编程辅助场景。OpenAI的Codex模型就是一个著名例子：它是在GPT-3模型的基础上，使用GitHub上大量公开代码进行了微调，从而具备了将自然语言描述转化为代码的能力

- **微调框架与工具：** 工程实践中，存在一些流行的框架来简化大模型微调的实现。最常用的是 **Hugging Face** 提供的工具集，它包括Transformers库中的Trainer等高级API，使我们无需手动编写训练循环就能微调模型；同时配套的PEFT库也实现了如LoRA、Prefix Tuning等高效微调方法，接口简单易用。另一个重要工具是 **DeepSpeed**（微软开源的深度学习优化库），它集成了一系列针对大模型训练的优化技术（比如上述的ZeRO分片、梯度检查点等）

  [blog.csdn.net](https://blog.csdn.net/qq_56591814/article/details/133221357#:~:text=目前最火的大模型训练框架DeepSpeed 详解来了)

  。开发者可以将Hugging Face的Trainer与DeepSpeed结合，在几行代码内开启大模型的混合并行微调

  [zhuanlan.zhihu.com](https://zhuanlan.zhihu.com/p/692340830#:~:text=AIGC周报精选,factory类似)

  。此外，还有诸如TensorFlow的GradientTape、PyTorch Lightning、Colossal-AI等框架，以及各大云厂商提供的分布式训练方案，都大大降低了实施微调的门槛。得益于这些工具，如今微调一个大语言模型不再是学术机构的专利，普通开发者也可以用少量GPU资源对公开的预训练模型进行优化，训练出适合自己任务的定制版LLM。

  

综上，参数微调为大型语言模型的落地应用打开了大门。从通用模型到任务专家，只需投入相对较小的成本，就能换来模型在特定场景下性能的大幅提升。无论是构建问答系统、智能写代码助手，还是行业垂直领域的AI专家，微调技术都是必不可少的一环。有了合理的数据、适当的方法和工具的支持，我们就可以让一个LLM更好地为手头的任务服务，发挥出更大的价值。每一次成功的微调，都是预训练知识与特定任务需求的一次高效结合。模型因此变得更加**懂行**，而这一切只需要我们善用参数微调这一关键步骤。
